# v0.1.0-alpha.3 hardware validation — pending

**Experimental firmware, website, tools and instructions are used entirely at your own risk.** Updates can leave the keyboard unusable or erase settings. Recovery may require external programming hardware and may fail. Retained stock and backups are not guarantees. [Full risk notice](../../RISK.md).

This is an unreleased candidate. No hardware tests are recorded yet. Automated checks, including modeled sleep entry, do not prove physical wake or current draw. The installed accepted alpha.2 has not been changed.

## Candidate identity

- Version: `0.1.0-alpha.3`
- Commit and exact OTA SHA-256: record only after final clean build and preflight checks.
- Board/revision, host and test date: pending.
- Power settings used for each test: record explicitly; proposed short test values are dim 2 s, off 4 s, sleep 10 s, relative brightness 20%.
- Trial/acceptance: unconfirmed mode changes and deep wakes consume trial boots. Never bypass the guard. Initial testing must fit its budget; self-test and acceptance require the owner's separate explicit acknowledgment after baseline/recovery checks.

## Hardware gates

- [ ] ON baseline: typing, Fn/media, backlight brightness/toggle, Caps fully on/off, Studio connect/unlock, saved mappings/layers intact.
- [ ] Settings: read actual defaults/current values; save changed dim/off/sleep/relative-brightness values; verify readback and invalid ordering rejection.
- [ ] ON lighting: dim then off at the configured deadlines; any physical activity restores selected brightness. A held key prevents dim/off. Manually disabled backlighting stays off after activity.
- [ ] BT with cable: USB/Studio absent, saved bond reconnects, typing/media/indicators work; configured connected sleep wakes with the first press/release and no stuck modifiers.
- [ ] BT on battery: repeated idle/suspend/wake; sample every row, both sides/modifiers and Fn. Cable insertion must not enable USB data or change endpoint policy.
- [ ] Manual retained-stock return and reinstall of the same exact candidate; no recovery guarantee inferred.
- [ ] Flash self-test/acceptance only after explicit owner authorization. Read back confirmed/count 0 before repeated restart/deep tests.
- [ ] BT disconnected deep sleep: after idle with the host unavailable, re-enable host and test key wake/reconnect. Record wake-key delivery and latency; distinguish observed behavior from inferred deep state.
- [ ] OFF: no keys/radio/lights/data; after the 20-second holdoff, selector movement to ON and BT works with and without USB power. Keys must not reactivate OFF.
- [ ] USB host suspend/resume: host resume restores typing/Studio/settings without unplugging. Keyboard remote wake tested only if host policy permits it; record any host limitation.
- [ ] Persistence: full power cycle retains power settings, mappings/layers and Bluetooth bonds; legacy output bindings cannot override selector policy; no stuck Shift after transport transitions.
- [ ] Current: compare active, dim, dark, connected suspend, disconnected deep sleep and OFF with suitable equipment; record supply/charging conditions and instrument resolution. USB charging draw is not automatically battery draw. No battery-life claim from an unmeasured test.
- [ ] Restore intended everyday timer settings and document known limitations before any release publication.

## Automated evidence

Record successful logs against the exact candidate hash, including shared codec/policy tests, secured settings and storage fault/persistence tests, encrypted BLE with simulated RF-register loss, entry-race/held-key tests, USB-host suspend, BT/OFF deep-entry masks, boot guard, importer, diagnostic variant, UI failure/retry/locking/navigation, pre-reset/final stack margins, clean source/site/archive audits and hosted subpaths.

The Python peripheral model supports retained suspend. It deliberately stops at deep entry; a manually reset model is not proof of electrical deep wake. Physical current and wake checks remain separate gates.
